# RIS5 Part A — foundations for the ideas engine — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** make conviction change and valuation observable per ticker so the Part B ideas engine can open New / Increase / Reduce / Sell ideas on real trends: (A1) every quarterly score recommendation becomes a dated row, (A2) every quarterly innovation/competition/AI read becomes a coded row with a direction, (A3) daily FactSet consensus/price snapshots plus weekly fundamentals start accruing and the stale Store B series is refreshed, (A4) the system gains bear-side paths, (A5) an expectations-gap valuation is computed per ticker.

## Task 1 (A1): Score-recommendation matcher + `score_reads.jsonl` backfill

**Files:** modify `scripts/thesis/match_evidence.py` (`_REC_RE` line 35, `lift_score_recs` 85-101); create `scripts/thesis/score_reads.py`, `scripts/thesis/test_score_reads.py`, fixtures `scripts/thesis/fixtures/score_reads/` (4 note excerpts covering every verb and the §5/§6-subblocks/§7 layout).

**Facts:** the reviewer's §5 (AI positioning), §6 (competitive advantage, with sub-blocks for innovation_rate / distribution / overall) and §7 (investor interest) sections end with a recommendation sentence using one of: `hold at N`, `drift to N`, `revise to N`, `propose N`, `propose initial score N`, `Populate as N` (N = `[1-5][+-]?`, sometimes bolded `**4**`). Corpus counts: hold 88 files, drift 37, revise 23, populate 2, propose 6. `lift_score_recs` today only matches drift/revise/propose and only runs on newly ingested earnings notes; AMAT's 2Q26 note carries four "Populate as" recommendations that never became data. The five score axes are `thesis_io.SCORE_KEYS`.

**Interfaces:**
- `score_reads.VERB_RE` = one regex capturing `(verb, value)` for all six verb forms (case-insensitive, tolerant of `**`, `:`, and "a"/"an" between verb and value); `parse_recs(note_text) -> list[{axis, verb, value}]` using the same section split `lift_score_recs` uses (reuse its helper; do not fork it).
- Row schema `{ticker, quarter (from the note filename, e.g. "2Q26"), date (ISO from filename), note_id ("<T>/<file>.md"), axis (one of SCORE_KEYS), verb ∈ hold|drift|revise|propose|populate, value, applied (the watchlist score at write time or null), ts}`; id = sha1 of `note_id|axis`; `append_rows(path, rows) -> {written, dupes}`.
- `match_evidence.lift_score_recs` uses `score_reads.parse_recs`; semantics unchanged for `proposed_scores` (hold/populate = no proposal; drift/revise/propose → proposal when ≠ applied) and additionally appends the rows to `state/thesis/score_reads.jsonl` on every ingest.
- CLI `python3 scripts/thesis/score_reads.py --backfill [--dry-run]`: walk `notes/<T>/*-<N>Q<YY>.md` and `*-conf-*.md`, parse, append (idempotent), print counts per verb and per axis; `--ticker T` filter.

**Tests:** every verb form incl. bold and "Populate as **4**"; axis attribution for §6 sub-blocks; idempotent append; a note without recommendations yields no rows; `lift_score_recs` proposal semantics unchanged (existing tests in `scripts/thesis/test_match_evidence.py` if present must still pass).

- [ ] Tests → implement → run new + existing thesis tests + `scripts/check.py` → `--backfill --dry-run` on the live vault and paste counts (expect ~150+ rows across ~95 notes; AMAT 4 rows) → run the real backfill (writes only `state/thesis/score_reads.jsonl`, which is TRACKED — add it to git) → commit `thesis: score-recommendation matcher + score_reads backfill (RIS5 A1)`.

## Task 5 (A5): Expectations-gap valuation — `scripts/valuation/expectations.py`

Per ticker with a price, market cap, and FY1–FY3 sales consensus (skip with reason otherwise):
- `implied_growth(ev, fy0_sales, fcf_margin_now, terminal_margin, discount_rate=0.10, terminal_growth=0.03, years=5) -> {implied_growth_5y, implied_terminal_margin, sensitivity: {dr±1pt, tm±3pt}}` — solve by bisection for the constant growth g such that PV(FCF over 5y with margin converging linearly to terminal_margin) + PV(terminal value at g_terminal) = EV; `terminal_margin` = config default per sector family (`config/valuation.yaml`: software 30%, semis 35%, hardware 12%, internet 25%, default 20%) overridable per ticker; EV = mcap + net debt (0 with a flag if fundamentals missing).
- `supported_growth(ticker) -> {base, downside, drivers}`: base = CAGR of consensus FY1→FY3 sales extended to 5y by a durability multiplier from (a) mean theme lifecycle stage of the ticker's themes (`state/topics/stages.json`; earlier stage → longer runway), (b) credibility (`state/chunk_store/credibility.json` consensus_beat_rate, guide_hit_rate), (c) the last-2-quarter reads trend (`state/thesis/reads.jsonl` direction/magnitude) — documented formula with bounds; downside = base minus a haircut when any assumption with a competition/margin theme is `challenged` (from `_thesis.md`), listing the assumption ids.
- `gap = implied_growth_5y − supported.base` (pp); `gap_downside`.
- Lenses: forward EV/Sales FY1 and P/E FY1; PEG-like = multiple / (consensus growth); z-scores vs own history from accrued snapshots (`n_days` shown; "insufficient history" below 60 daily points) and vs theme peers (tickers sharing ≥ 2 themes, median); revision breadth from consensus snapshots (up−down counts, 4w/13w; "n/a" until history exists).
- Outputs: `state/valuation/expectations_<date>.jsonl` (gitignored) + tracked `state/valuation/expectations_latest.json`; `scripts/portal/state_bundles.py` gains `data/valuation.json` (per ticker: all layers with inputs and as_of; `valuation_extreme` flag per the spec thresholds: gap > +8pp or PEG-vs-history z > +2).
- Tests: bisection reproduces a synthetic EV within 0.1%; sensitivity monotonic; supported-growth bounds; gap sign; missing inputs → skipped with reason; bundle shape.

- [ ] Tests → implement → live run on the first day of snapshots (paste NVDA/AVGO/COHR cards) → commit `valuation: expectations-gap module + data/valuation.json (RIS5 A5)`.
