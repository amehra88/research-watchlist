# RIS4 — Research Information System, plan v4 (2026-09-15)

Mobile portal as a claude.ai Artifact, fed by the DigitalOcean droplet. Refer to this plan as **RIS4**. Canonical copy: `/root/.claude/plans/staged-jingling-feigenbaum.md`; repo copy for offline review: `docs/superpowers/specs/2026-09-15-RIS4-plan.md` (synced to GitHub/Obsidian).

## Review verdict (2026-09-15, after operator challenge)
Too ambitious as one build. Ship in **slices**, each verified on the phone before the next: (1) smoke test ½d → (2) read-only portal Today/Tickers/Themes/Ideas/Scores/Search 1.5d → (3) Ask ½d → (4) live panels ½d → (5) input channel 2d, captures+notes first, decisions second, appliers in **stage-and-email mode** before any auto-apply → (6) novel-names engine ½d (§6.4) feeding the Ideas tab. Deferred out of the first pass: photo uploads (behind the `fileArgs` check), db read markers (localStorage first), theme-candidate accept from the phone (CLI exists). Out of scope by decision: DCF/valuation (see Part 2), charts.

## Context

The operator cannot reach Obsidian at work and wants "our own research information system": an interactive, menu-driven app usable from the iPhone Claude app, that (a) browses the vault and the daily digests, (b) asks Claude questions over the corpus, (c) shows live market/insider data, and (d) works as an **input channel** (notes, photos, decisions, add/remove tickers). The droplet stays the vault's home (git → GitHub → Obsidian unchanged); Obsidian stays the editing surface at home.

Verified constraints that shape the design:
- Artifacts: page ≤16MB, ≤255 files, ≤64MB/version; CSP blocks all fetches except same-origin files and a few CDNs → the page **cannot reach the droplet**; data ships as published files, live data comes only through the viewer's claude.ai connectors.
- Available runtime capabilities: `sample` (ask Claude, 64KiB/call, page tools allowed), `mcp` (FactSet, InsiderScore, Gmail with the viewer's credentials), `db` (≤5,000 docs, shared), `assets` (uploads), `artifact`, `downloads`, `room`. `user` is NOT available → no per-viewer paths; fine, single operator, org-internal.
- Headless `claude -p` on the droplet has **no Artifact tool** (tested) → the droplet builds the bundle; a Claude Code session publishes it. Cloud-routine publishing is untested (Phase 0 test).
- Vault: curated set is 10.2 MB / 909 files (ships whole). news 31MB/20.8K files and sec 325MB/8.1K files → windowed (30 d, trimmed). 77 of 109 dated ticker notes have no frontmatter → parse filename. 96 of 182 watchlist tickers have no display name → one-time backfill. Several state files the theme/flows views need are gitignored → the build must run on the droplet. Wikilinks in 3 shapes; GFM tables; no callouts. `auto_sync` does `git add -A` every 15 min → build output must be gitignored.
- Comparable projects (YouRich, Anthropic's equity-research skill bundle, Karpathy llm-wiki) have nothing mobile, but contribute: change-since-last-visit diffs, provenance labels, forward-looking views (upcoming events, earnings scorecard), a wiki-health panel, and "file answers back". Vision-LLM chart reading is unreliable (51% direction, 1/215 patterns in an Apr-2026 audit); charts are **deferred by the operator** for this build. When they return, the rule is: draw from FactSet OHLCV and compute indicators deterministically; Claude narrates numbers, never pixels.
- Tool schemas verified in this session (ToolSearch + one real call each): Gmail `send_message{to[], subject, body, attachments[{content(base64), filename, mimeType}]}`; InsiderScore `get_company_info{tickerlist[]}` → `[{ticker, companyname, sector, industry, marketcap, current_stock_price, current_stock_price_date}]` (bare tickers; **use this for the name backfill and the cheap price header**); `get_insider_transactions{tickerlist, txntypes, tenb5, use_disclosure_date, begin_date, end_date, limit}` → `result` is a **CSV string** (parse client-side); FactSet `FactSet_GlobalPrices{ids:["NVDA-US"], data_type:"prices", startDate, endDate?, fields}` → `data:[{date, price, volume, requestId, currency}]`; `FactSet_EstimatesConsensus{ids, estimate_type:"consensus_rolling", metrics:["EPS"], periodicity:"QTR", relativeFiscalStart:1, relativeFiscalEnd:1}` → `data:[{fiscalPeriod, fiscalYear, fiscalEndDate, mean, median, estimateCount, up, down}]`. Never embed these observed values in the page as sample data.

## Menu (agreed wireframe)

Bottom tabs: **Today** · **Tickers** · **Themes** · **Ideas** · **More** (Scores, Capture, Reports archive, ETF flows, Search, Status/Health). Scores stays one tap away in More and is linked from every ticker's Signals sub-tab and from the Today card "proposed score changes"; Capture is reachable from every ticker/theme/idea screen and the Today header. (Operator may swap Ideas↔Scores in the bar; it is one constant.)

**Ideas tab (operator requirement: investment idea surfacing).** The idea-surfacing engine already exists — it is the theme-diffusion system (spec `docs/superpowers/specs/2026-08-11-idea-surfacing-timeliness-design.md`, P2–P5b live). What is missing is one surface with actions, plus the spec's unbuilt §6.4. One queue, six streams, each row with **Ask why / Dismiss / Act**:
1. **New-theme candidates** (`state/topics/candidates.json`, 8 pending) → Accept (+name) / Reject.
2. **Newly said** (`diffusion.json.newly_said`, current quarter, tiers 1–2 first, sorted by n_banks) → open theme / add thesis question.
3. **Evidence without question** (§6.2 gap rows from `diffusion.json.metrics`) → watch.
4. **Stage transitions** (`state/topics/detections.jsonl`, 13) → open theme/ticker.
5. **Untracked names from the AI screens** (latest `docs/ai-screen-report-*.md` cross-signal table, rows not marked *tracked*) → Add to tier_3 / Dismiss.
6. **Novel names (§6.4, NEW ENGINE, ~½ day)**: `scripts/topics/novel_names.py` — entity mentions in `state/transcripts/exchanges.jsonl` that resolve to nothing in watchlist / `private_drivers` / `tier_4_ecosystem` (the `entities.py` alias-resolution residual), ranked by distinct companies × distinct banks mentioning them, written to `state/topics/novel_names.json` by the Saturday chain → Add to tier_3 / Add as private_driver / Dismiss. Operator decides; the system never writes the watchlist itself.
Dismissals and acts are queued decisions (`idea_dismiss`, `ticker_add`, `theme_accept`…); the build reads `state/portal/ideas_decisions.jsonl` so dismissed ideas do not return. `ideas.json` is built by `state_bundles.py` from those six sources with stable ids (`<stream>:<key>`).
Ticker page sub-tabs: **Notes · Thesis · Signals · News · Insiders**, with *Ask about T* and *Capture for T*. (Charts deliberately deferred; no Chart tab.)
**Scores tab (operator request: moat scores from the menu, with my read and recommended changes).** Cross-ticker table for tier 1 and 2: AI positioning, competitive advantage (innovation rate / distribution / overall), investor interest — current score from `watchlist.yaml` + `_thesis.md`, **proposed change** from `_thesis.md.proposed_scores` and `thesis_report.pending_proposals`, and **my read** = the latest earnings review's §5/§6/§7 signal sentences (per quarter, with the note link). Sort by "biggest proposed change" / "most recent read"; filter by theme. Each row expands to the per-quarter history and has **Approve / Reject / Edit score** → queued decision (`score_decision`) → applied on the droplet via `thesis_io.save` + the existing `apply_scores` path. This is the same data the per-ticker Signals sub-tab shows, pivoted across tickers.
Non-ticker: Today (digest cards + Upcoming + "what changed since last visit" + unread), Themes (accepted with stage arrows, candidates ✓/✗, diffusion breadth), Capture (tag picker, text, photo/PDF, queued decisions, sent history).
Out of scope by operator decision: DCF / valuation models, peer valuation tables, charts (deferred, not dropped: FactSet OHLCV is available whenever charts come back).
Add/remove tickers = queued decisions applied on the droplet (never direct config edits from the phone).

## Notes channel — operator notes, sell-side notes, industry notes (operator requirement)

Three note kinds, all entered from Capture (text/dictation, pasted text, or an uploaded .md/.pdf) or from *Capture for T* on a ticker screen, all **append-only**:

| kind | required metadata | filed to | provenance / retrieval weight | consumers |
|---|---|---|---|---|
| `operator_note` | tickers[] or themes[] | `notes/<T>/YYYYMMDD-operator-<slug>.md` (or `notes/sector/` when theme-only) | `operator` — **highest** (`SOURCE_WEIGHT["operator"]=1.2` in `scripts/chunking/store.py`) | inbox_processor summary → pg chunks → `thesis/sources.py` (already reads `notes/inbox/*.summary.md`) → match_evidence; earnings reviewer prompt gains "operator notes since last quarter" |
| `sell_side_note` | broker, analyst, date, rating, price target, tickers[] | `notes/<T>/YYYYMMDD-sellside-<broker>-<slug>.md` | `sell_side` — **below primary** (0.9); rating/PT kept as frontmatter only; standing rule: sell-side last priority, rating change counts only with non-valuation rationale | same pipeline; Scores tab shows sell-side reads in a separate, de-emphasised column |
| `industry_note` | themes[], tickers covered[] | `notes/sector/YYYYMMDD-industry-<slug>.md` + `[[...]]` link from each covered ticker's `_themes.md` index | `industry` (1.0) | same pipeline; Themes tab lists industry notes under each theme |

Mechanics: Capture composer gets a **kind selector** with the metadata fields above; text goes in the Gmail envelope; `.md`/`.pdf` ≤ ~700 KB inline as a base64 attachment (verified `attachments[]` field), larger files → `assets` store + asset id in the envelope; a session step (`portal-sync-assets` in the runbook, `read_asset`) pulls large PDFs into `notes/inbox/attachments/` until Phase 5. Droplet: `inbound_poller.py` extracts PDF text with `/usr/bin/pdftotext -layout`, writes `notes/inbox/portal-<id>.md` with `process: note`, `note_kind`, the metadata, and the extracted text; `inbox_processor.py` synthesizes the desk summary; a small `place_note()` step in the poller moves the final note to the target folder above with the frontmatter contract (`doc_type: operator_note|sell_side_note|industry_note`, `provenance`, `source_org`, `analyst`, `rating`, `price_target`, `tickers`, `themes`, `captured_at`). Chunker: add the three `doc_type`s to `SOURCE_WEIGHT`. Licensing: sell-side PDFs stay in the private vault; the artifact is org-internal; never publish PDF bodies into the bundle (summaries + metadata only).

### Part 2 (separate spec, after slices 1–4 are live) — "Expectations", not DCF
Per-ticker view: consensus + revisions (FactSet EstimatesConsensus, already pulled for Store B), guidance-vs-consensus-vs-actual track record and credibility (Store B), **expectations-implied growth** computed deterministically from price + consensus (reverse-DCF-lite, inputs shown), and **scenario ranges tied to thesis assumptions** ("if assumption X breaks → this metric at risk"), plus an earnings scorecard per quarter. LLM narrates numbers only. No spreadsheet models, no peer valuation tables.

## Other things to keep in view
- Bundle file count: emit `data/tickers/<T>.json` only for tickers with notes (99 today) and group the rest into `data/tickers/_index.json`; the 255-file cap is otherwise reached as the watchlist grows.
- First load on cellular: manifest first (~60 KB), everything else lazy; show "as of <built_at>" on every screen.
- Cost: `sample` spends the operator's subscription (Ask-with-tools = 3–5 rounds, explicit button only); build cron = $0; each capture = one small inbox_processor `claude -p`.
- Trust visibility: every note/card shows provenance; nothing is operator-reviewed today — the Scores/Thesis screens are the place to change that.
- Keyword search on the page vs semantic search in pg: the page's search is postings-based; the good retrieval arrives with Phase 5.
- Sharing: keep the artifact private; connectors are granted per page on first use; the page never stores secrets.
